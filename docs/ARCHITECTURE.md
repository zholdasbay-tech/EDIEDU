# Архитектура EdiEdu

## Схема

```
 Браузер (HTML + CSS + JS-модули, графики на SVG)
      │  fetch /api/...   Authorization: Bearer <токен>
      ▼
 FastAPI (backend/app/main.py)
      ├─ schemas.py   — проверка входных данных (Pydantic)
      ├─ auth.py      — PBKDF2-пароли, сессии, лимит попыток входа
      ├─ analytics.py — pandas + SciPy: норма, выбросы, закономерности, индекс, эксперименты
      ├─ school.py    — агрегаты по классам, k-анонимность, сигналы
      └─ seed.py      — синтетические демо-данные
      │
      ▼
 SQLite (db.py): schools, classes, users, sessions, checkins, experiments
```

Один процесс отдаёт и API, и статические файлы сайта. Это одна ссылка и один деплой, CORS не нужен.

## Путь одного запроса: «Сохранить день»

1. `app.js` → `PUT /api/checkins/2026-09-23` с JSON.
2. FastAPI проверяет токен (`current_user`) и роль (`student`).
3. Pydantic (`CheckinIn`) проверяет диапазоны: настроение 1–5, сон 0–16 ч, метки только из списка, заметка до 280 символов.
4. Сервер проверяет дату: не в будущем и не старше 7 дней.
5. `INSERT OR REPLACE`: один день = одна запись (первичный ключ `user_id + date`).
6. Фронтенд запрашивает `GET /api/insights` → `analytics.build_insights()` пересчитывает всё по последним 120 дням (≈0,2 с).

## Данные

| Таблица | Что хранит | Важное |
|---|---|---|
| users | логин, хеш пароля, соль, роль, класс, флаг «делиться» | пароль не хранится |
| sessions | SHA-256 токена, срок | сам токен не хранится |
| checkins | 8 показателей, метки, заметка | PK (user_id, date) |
| experiments | название, метрика, старт, длительность | результат считается на лету |
| schools, classes | название, код класса | |

Удаление пользователя каскадом удаляет отметки, эксперименты и сессии (`ON DELETE CASCADE`).

- **Готовое:** FastAPI (веб-сервер), Pydantic (проверка данных), pandas (таблицы), SciPy (`spearmanr`, `mannwhitneyu`, `linregress`), SQLite.

## Шпаргалка к вопросам жюри

**Почему не нейросеть?**
Для одного ученика у нас 30–90 точек. Нейросеть на таком объёме переобучится и не сможет объяснить свой ответ. Статистические тесты работают на малых выборках, и их вывод можно объяснить ученику одной фразой.

**Почему Спирмен, а не Пирсон?**
Настроение и стресс измеряются по шкале 1–5, это порядковые данные. Спирмен работает с рангами и не требует нормального распределения.

**Что такое поправка Бенджамини–Хохберга?**
Мы проверяем 9 пар сразу. При пороге p < 0,05 и отсутствии реальных связей шанс получить хотя бы одну ложную «находку» около 37% (1 − 0,95⁹). BH контролирует долю ложных находок. Тест `test_no_patterns_on_pure_noise` это подтверждает: на 40 наборах случайного шума ложных находок не больше 15%.

**Почему медиана и MAD, а не среднее?**
Одна бессонная ночь сильно сдвигает среднее, а медиана к таким выбросам устойчива.

**Откуда веса индекса?**
Их выбрала команда по смыслу: сон и стресс весят больше всего. У нас нет размеченных данных «выгорел / не выгорел», поэтому индекс — сигнал, а не диагноз. План: откалибровать веса с психологами на пилоте.

**Откуда демо-данные? Это не фальсификация?**
Данные синтетические, и это подписано на каждом демо-экране. Генератор (`seed.py`) моделирует известные из исследований эффекты. Мы используем его, чтобы проверить, что аналитика находит заложенные связи и не находит несуществующие. Результатов на реальных людях мы не заявляем.

**Как защищены данные?**
PBKDF2 (200 000 итераций) для паролей, в базе хранится только хеш токена, лимит попыток входа, параметризованный SQL, проверка всех входных данных, пользовательский текст не вставляется как HTML, CSP-заголовки. Школа видит только агрегаты по группам от 5 человек.

**Как масштабировать?**
SQLite → PostgreSQL (схема та же). Лимит входа в памяти → Redis. Расчёт аналитики уже работает независимо для каждого ученика, поэтому сервер масштабируется горизонтально.

**Почему не приложение в App Store?**
Сайт открывается на любом телефоне без установки, его проще проверить жюри и проще внедрить в школе. Добавить его на главный экран (PWA) — следующий шаг.
